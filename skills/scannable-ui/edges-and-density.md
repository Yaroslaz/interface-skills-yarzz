# Края и плотность: рецепты

## Найти края

Края — это не только границы контейнера. Это любая прямая, которую видит глаз:

| Край | Пример |
| --- | --- |
| Внешний край контейнера | Левый край карточки, правый край строки таблицы |
| Нижний край блока | Низ аватара с именем — на него встаёт следующий ряд |
| Линия строки | Каждый пункт чек-листа — край для следующего |
| Колонка значений | Правый край цен на чеке, колонка чисел в таблице |
| Созданный край | Кнопки и аватар, выровненные в одну линию, — новый «верх» для содержимого ниже |

Почти любой компактный интерфейс — поле чата, карточка канбана, боковая панель — держится на том, что **каждый элемент касается двух и более краёв**.

## Выравнивание

- Текст — к началу строки, числа — к концу (`text-align: end`), моноширинные цифры (`font-variant-numeric: tabular-nums`).
- По центру — только то, что не нужно читать построчно: пустые состояния, коды, иллюстрации.
- Одна величина отступа на уровень вложенности; не вводи новый отступ для каждого блока.
- Логические свойства (`margin-inline-start`, `inset-inline-end`) вместо `left/right` там, где интерфейс может зеркалиться.

```css
/* Чек: два края, никаких разделителей */
.receipt-row {
  display: flex;
  justify-content: space-between;
  gap: 16px;
}
.receipt-row > :last-child {
  text-align: end;
  font-variant-numeric: tabular-nums;
}
```

## Создать край вместо пустоты

```text
Плохо:  [аватар] Имя                  ← справа пусто, «добавим кнопок»
        [Кнопка][Кнопка][Кнопка][⋮]   ← кнопки не касаются ни одного края

Лучше:  [аватар] Имя         [Кнопка] ← кнопка и аватар на одной линии:
        ─────────────────────────────    это новый верхний край
        Содержимое встаёт на эту линию
```

## Плотность и различение

1. **Не добавляй воздух первым.** Он делает экран длиннее, а читать его не легче.
2. **Различи типы содержимого:** люди — аватарами, категории — чипами, ссылки — цветом и подчёркиванием, статусы — точкой с подписью.
3. **Сгруппируй по вопросу пользователя:** задачи — по сроку, студенты — по статусу работы, вопросы — по теме.
4. **Отдели группы пространством:** внутри группы `8px` — между группами `16px` и больше. Линии — только там, где пространства не хватает (таблицы, длинные списки настроек), и то тонкие и бледные.

## Таблицы

- **Без вертикальных разделителей.** Колонки держит выравнивание (текст — влево, числа — вправо и моноширинными цифрами), строки — тонкая горизонтальная линия. Вертикальная линия в каждой строке — это десятки лишних краёв.
- **Заголовок колонки не обрезается** на целевой ширине (1440px): ширины подбираются под самые длинные подписи, а не наоборот. Многоточие в заголовке — признак, что колонку надо сократить по смыслу («Не сдали» вместо «Не сдали тест»).
- **Заголовки колонок тихие:** обычная насыщенность (`500`), серый цвет, одна строка. Заголовок читают один раз, значения — постоянно; жирная строка заголовков спорит с данными за первый взгляд.
- **Родственные счётчики — одной записью через слеш**, как K/D/A в играх: «Начали / завершили / назначено» → заголовок `Н / З / В`, значение `6 / 6 / 8`. Три колонки с заголовками в две строки превращаются в одну узкую. Правила записи:
  - заголовок — по одной букве на число; расшифровка — списком «буква — значение» во всплывающем блоке (наведение мышью, нажатие на телефоне);
  - у значения своя расшифровка с числами («К проверке 1, К решению 0…»); нажатие по значению на телефоне не открывает строку;
  - нули в записи серые по отдельности — `0 / 0 / 2` сразу показывает, где не ноль;
  - для скринридера — полный текст рядом (`aria-hidden` у записи, скрытая подпись с расшифровкой);
  - всплывающему блоку на нефокусируемом тексте роли не нужны (`aria-expanded` на `span` — ошибка axe).
- **Подпись к значению по умолчанию не пишут:** «Индивидуально: 0» убирается, «+2 студента» появляется только когда не ноль, и в одну строку.
- **Умолчания приглушены:** `0`, `0 %`, `—` — серые; статус по умолчанию («Активна») — серым текстом без цветной точки. Тогда «3 к проверке» и «Закрыта» находятся сами.

## Поля до края

Поля ввода в форме доходят до правого края формы. Кнопка удаления строки (варианта ответа, условия) — внутри поля справа (`rightSection`), а не отдельной узкой колонкой: колонка с крестиком отрезает у всех полей общий правый край и оставляет дыру там, где удалять нельзя.

## Боковое меню сворачивается

Колонка навигации шириной 240px нужна, пока её читают; привыкшему человеку хватает значков. Кнопка в строке логотипа сворачивает её до 64px:

- значки остаются **на тех же высотах** — подпись сжимается до нулевой ширины, а не вынимается из потока, иначе пункты съезжают;
- подпись — в подсказке справа по наведению и для скринридера (остаётся в ссылке);
- выбор запоминается (`localStorage`), и об этом сказано в уведомлении о хранилище;
- выдвижная панель на телефоне всегда развёрнута.

## Широкие экраны

Строка во всю ширину монитора теряет края: глаз не может перейти от названия к значению. Ограничь ширину чтения (`max-width: 65ch` для текста), а связанные значения ставь рядом, а не по краям экрана.

## Проверки

- Закрой глаза наполовину (или размой скриншот): видны ли вертикали, на которых стоит содержимое? Если вместо них «шум» — краёв не хватает.
- Найди элемент, который не касается ни одного края. Это кандидат на перенос или на создание нового края.
- Сосчитай одинаковые по виду строки подряд. Больше пяти-семи — их нужно различить или сгруппировать.
