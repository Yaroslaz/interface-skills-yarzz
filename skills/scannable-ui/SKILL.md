# Сканируемый интерфейс

Люди не читают экран. Они приходят с вопросом в голове и **ищут** ответ: один файл в редакторе, одну настройку в панели, одного студента в ведомости. Ни один экран не потребляется целиком. Хороший интерфейс от этого не красивее — он **быстрее просматривается**, и при этом никому не говорит, откуда начинать.

Этот скилл собирает приёмы, которые делают экран «странно идеальным». Каждый приём — инструмент сканирования: края, различение, визуальные метки и контраст.

Правила проверяются на живом экране, а не в коде. Если проект уже задаёт сетку, отступы, токены — пиши исправления в его системе. Остальные стороны интерфейса (доступность, типографика, цвет, тексты, анимация) отдай профильным скиллам, если они подключены, например набору [`jakubkrehel/skills`](https://github.com/jakubkrehel/skills).

## 1. Края держат содержимое

На чеке нет ни одного разделителя и почти нет пустого места, а читается он легко: текст прижат к левому краю, цены — к правому. По центру только то, что читать не нужно (коды, штрихкоды). Два края держат всё.

- Каждый элемент опирается **минимум на два края**: край контейнера, край соседнего блока, линию строки над ним.
- Пустое место не заполняют контентом, чтобы «не пустовало». Вместо этого ищут края, к которым можно пристроить содержимое: у карточки четыре края, а ещё — нижний край аватара с именем, на который можно ставить следующий ряд.
- Если краёв не хватает, **создай край**: опусти верхнюю границу, выровняв кнопки и аватар в одну линию, — содержимое ниже встанет на неё.
- Скрывать элементы в меню ⋮, чтобы «стало чище», — последнее средство, а не способ навести порядок.
- Иконка крупнее строки ломает нижний край — верни его подписью-подстрочником.
- Строка, растянутая на всю ширину огромного экрана, теряет края: длина строки ограничена, связанные значения стоят рядом.

Подробные рецепты и проверки — в [edges-and-density.md](edges-and-density.md).

## 2. Плотность — не враг; враг — неразличимое

Добавлять воздух против плотности — частая ошибка: стало чуть легче и сильно длиннее. Проблема не в количестве содержимого, а в том, что оно **одинаковое**.

- Различай содержимое: аватар там, где упомянут человек; группировка по смыслу (по сроку, по статусу) — и любой пункт находится за секунду, сколько бы текста ни было.
- Списки, таблицы и маркированные пункты работают потому, что различают содержимое, а не потому что «структурируют».
- Группируй пространством: зазор между группами минимум вдвое больше зазора внутри группы.

## 3. Визуальное вместо текста

Красный восьмиугольник — «стоп» ещё до чтения. Узнаваемый образ считывается мгновенно, текст — нет.

- Когда непонятно, первый порыв — объяснить подробнее: добавить подпись, сравнение, подсказку. Каждое добавление — «больше информации», но экран становится труднее читать ради того, чтобы стать проще понять. Этот обмен почти никогда не выгоден.
- Заменяй повторяющийся текст узнаваемыми знаками: значок статуса вместо слова «Статус:», чип категории вместо строки «Категория: …», синий подчёркнутый текст для ссылок.
- Значок без подписи допустим, только если он **общепринятый** или его смысл ясен из положения (флажок над списком). Иначе — значок с подписью; подсказка по наведению не заменяет подпись (на телефоне её нет).
- Чипы дают ещё и действие: тег можно сменить прямо в строке, а не через меню.
- **Пояснение раздела** («Здесь находятся группы, к которым…») — в значок ⓘ рядом с заголовком. Он открывается **нажатием** (всплывающий блок, не подсказка по наведению — на телефоне наведения нет), наведением мышью — тоже. Текст пояснения связан со значком через `aria-describedby`, чтобы его слышал скринридер.

## 4. Акцент — это разница с соседями

Флажок в выключенном состоянии — тонкая рамка, во включённом — заливка и галочка. Никто не делает его синим, когда он выключен: цвет и есть сигнал, что что-то изменилось.

- **Значения по умолчанию — серые.** Тогда отличающиеся находят взгляд сами. Шесть ярких чипов «по умолчанию» — это шесть флажков, синих в выключенном состоянии.
- Чтобы выделить элемент, не добавляй ему цвета и жирности — **измени окружение**. Единственный синий элемент в меню — тот, на который хотят обратить внимание.
- Один главный акцент на экран: одна первичная кнопка, один выбранный пункт навигации.

## 5. Меньше коробок

Карточка даёт четыре края бесплатно, поэтому всё строят карточками — и получают рамки в рамках и три разных радиуса друг в друге.

- Одна линия колонки может заменить край карточки. Каждая строка опирается на строку над ней, секции группируют, чипы и значки читают за пользователя, умолчания серые.
- Вложенные поверхности — только когда группа действительно должна читаться одним объектом (выбираемая строка, перетаскиваемая карточка). Тогда внешний радиус = внутренний + отступ.

## 6. Телефон: то же, но жёстче

На узком экране все приёмы выше обязательны, а не желательны. Кабинет с таблицами, фильтрами и формами адаптируется так:

- **Навигация — островом снизу**, 4 главных раздела + «Ещё»; бургер в верхнем углу на телефоне недостижим для большого пальца.
- **Таблицы не листаются вбок.** Строка становится двумя линиями: название и 2–3 главных значения «подпись значение». Остальные колонки скрыты — они есть в самой записи, куда ведёт строка.
- **Формы — шторкой снизу** во всю ширину: кнопки действия под пальцем.
- **Пояснения раздела** спрятаны в ⓘ (раздел 3); данные записи в подзаголовке вложенного экрана остаются.
- **Кнопки шапки** — одной строкой: главная растянута, второстепенные со значком — только значком, редкие — в меню «⋯».

Рецепты, значения и проверки — в [mobile.md](mobile.md).

## 7. Шапки и блоки-сводки

Шапка раздела, карточка записи, плашки параметров — блоки, которые видят первыми. Типичная беда: каждый «вырос» по своим правилам, и экран состоит из дыр и разных расстояний.

- **Одна строка шапки:** заголовок слева, действия справа — на одной линии. Фильтры раздела — тоже в эту строку, а не отдельным рядом под ней: отдельный ряд с одной кнопкой справа оставляет дыру слева.
- **Один шаг до содержимого:** расстояние «шапка → первый блок» везде одинаковое (например, `12px`), и не складывается из отступа шапки, отступа страницы и отступа блока.
- **Карточка-сводка — три линии:** название и статус; факты значками в одну строку (`📊 64 %`, `⚠ 3 события`, `📅 12 окт`); действия в ряд, главное — справа. Длинный текст (причина, комментарий) — максимум две строки, остальное раскрывается. Подписи «Результат:», «Дата:» не нужны, если значок узнаётся.
- **Плашки параметров:** главные (тест, группа, срок) — всегда; технические (контроль вкладки, режим прокторинга) — серые, а на телефоне скрыты: они есть в настройках.
- **Сводные цифры** (плитки дашборда): ноль — серый и обычной жирности; цветом и весом выделяются только ненулевые.
- **Текст на кнопке не превращается в значок**, если значка в нём нет: «Ведомость →» остаётся словом; значком становятся только кнопки, у которых значок уже стоит слева от подписи.

## Как применять

1. **Сформулируй вопрос пользователя** для экрана: «кому я не выставил оценку?», «где идёт тест?». Экран отвечает на него первым, остальное — потом.
2. **Пройди экран глазами по краям.** Всё ли лежит на общих вертикалях и строках? Где элемент висит, не касаясь края?
3. **Найди неразличимое.** Где одинаковые строки текста, которые можно различить значком, группой, чипом, аватаром?
4. **Проверь умолчания.** Что окрашено, хотя ничего не сообщает? Сделай это серым — и посмотри, что осталось ярким.
5. **Сними лишние коробки.** Где рамка внутри рамки? Можно ли заменить её линией или пространством?
6. **Сожми экран до 390 и 320 пикселей.** Нет ли горизонтальной прокрутки, обрезанных колонок, кнопок вне досягаемости пальца?

## Перед тем как закончить

| Признак | Исправление |
| --- | --- |
| Пустое место «заполнено» элементами, чтобы не пустовало | Пристрой содержимое к существующим краям или создай новый край |
| Второстепенные действия убраны в ⋮ ради «чистоты» | Сначала выровняй их по краям; прятать — последнее средство |
| Отступы увеличены, чтобы бороться с плотностью | Различи содержимое: группы, значки, аватары, чипы |
| Подсказка, сноска или пояснение добавлены, чтобы «объяснить» | Замени узнаваемым образом или переставь элемент так, чтобы смысл дало положение |
| Все чипы и метки цветные | Умолчания — серые; цвет только у отличающихся значений |
| Акцент усиливается цветом и жирностью самого элемента | Приглуши соседей |
| Рамка внутри рамки, разные радиусы друг в друге | Линия колонки или пространство; внешний радиус = внутренний + отступ |
| Таблица на телефоне листается вбок | Двухстрочная строка с главными колонками (mobile.md) |
| Навигация на телефоне — бургер в верхнем углу | Нижний остров с главными разделами и «Ещё» |
| Модальное окно на телефоне — карточка посередине | Шторка снизу во всю ширину |
| Под заголовком абзац «О разделе» | Значок ⓘ с всплывающим пояснением по нажатию |
| Фильтры или одна кнопка — отдельным рядом под шапкой | Перенеси в строку шапки, к остальным действиям |
| Отступ от шапки до содержимого разный на разных экранах | Один шаг; отступы не складываются |
| Карточка-сводка в 6–8 строк с подписями «Поле: значение» | Три линии: название, факты значками, действия |
| Три-четыре колонки родственных счётчиков с заголовками в две строки | Одна колонка K/D/A: `Н / З / В` → `6 / 6 / 8` с расшифровкой по наведению и нажатию |
| Жирные заголовки колонок | Обычная насыщенность, серый, одна строка |
| Боковое меню нельзя свернуть, таблицам тесно | Кнопка «Свернуть меню» до колонки значков с подсказками |
| Вертикальные линии между колонками таблицы | Только горизонтальные разделители строк; колонки держит выравнивание |
| Кнопка удаления — отдельной колонкой рядом с полем | Внутри поля справа; поле доходит до края |
